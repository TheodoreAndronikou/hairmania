# Εγκατάσταση από το μηδέν

Πώς στήνεται όλο το σύστημα σε καθαρούς λογαριασμούς. Χρειάζεται αν
μεταφέρεις το έργο σε νέα ιδιοκτησία ή αν το ξαναστήνεις για άλλο μαγαζί.

Χρόνος: ~40 λεπτά.

Δες πρώτα το **ΠΑΡΑΔΟΣΗ.md** για το τι είναι το κάθε κομμάτι.

Κράτα κάθε κωδικό και κλειδί που θα δημιουργηθεί στα παρακάτω βήματα σε
διαχειριστή κωδικών — όχι σε σημειώσεις ή μηνύματα.

---

## Α. Η βάση (15΄)

1. **supabase.com** → Sign in with GitHub → **New project**.
   Περιοχή: *Frankfurt* (πλησιέστερη στην Ελλάδα).
   Κράτα τον κωδικό της βάσης που θα σου δώσει.

2. **SQL Editor** → New query → επικόλλησε **όλο** το `supabase/schema.sql`
   → **Run**.

   > Τρέξε **ΧΩΡΙΣ RLS**. Ο SQL Editor μπορεί να σε ρωτήσει. Οι πίνακες
   > είναι σκόπιμα κλειδωμένοι· με RLS ενεργό τα `insert` δεν περνάνε και
   > **δεν παίρνεις μήνυμα λάθους**.

3. Ίδια διαδικασία, με αυτή τη σειρά, για `supabase/patch-01.sql`,
   `supabase/patch-02-email.sql`, `supabase/patch-03-backup.sql`,
   `supabase/patch-04-security.sql` και `supabase/patch-05-lockout.sql`.

   **Τα δύο τελευταία μην τα παραλείψεις.** Χωρίς το patch-04, ο κωδικός
   του διαχειριστικού διαβάζεται από οποιονδήποτε· χωρίς το patch-05,
   μαντεύεται χωρίς όριο. Το patch-05 δείχνει στο τέλος πίνακα: πρέπει
   να βγουν 13 συναρτήσεις με `true` και 5 με `false`.

4. **Settings → API** → αντίγραψε *Project URL* και *anon public key*.

5. Άλλαξε τον κωδικό του διαχειριστικού από το εργοστασιακό `1234`:

   ```sql
   update settings set value = 'δικος_σου_κωδικος' where key = 'admin_pin';
   ```

   Αν ξεχαστεί, το διαχειριστικό εμφανίζει κόκκινη προειδοποίηση.

## Β. Το site (10΄)

1. **Δύο** repositories στο GitHub:
   - ένα **Private** για τον κώδικα (π.χ. `κατάστημα-source`) — εκεί
     ανεβαίνει όλο το project με `git push`
   - ένα **Public** για το site — εκεί γράφει μόνο το `publish.mjs`.
     Πρέπει να είναι δημόσιο, γιατί το δωρεάν GitHub Pages δουλεύει μόνο
     σε δημόσια repos.

2. Στο `site/assets/js/config.js` βάλε τα στοιχεία του βήματος Α4:

   ```js
   SUPABASE: {
     url: 'https://<ref>.supabase.co',
     key: 'eyJ...'          // δημόσιο anon key — σωστά ορατό
   }
   ```

   Στην ενότητα `business` ενημέρωσε όνομα, τηλέφωνα, διεύθυνση, social.
   Για νέο κατάστημα πρόσεξε και τα: `brandTop`/`brandSub` (το λογότυπο
   γράφεται σε δύο γραμμές), `cityEn` (η πόλη με λατινικούς για τα
   αγγλικά) και `cityIn` (η πόλη με το άρθρο: `στα Γιαννιτσά`, `στη
   Θεσσαλονίκη` — τα ελληνικά δεν κλίνονται αυτόματα).

   Στις ενότητες `hours` και `services` βάλε το ωράριο και τις τιμές του
   καταστήματος — **και τα ίδια ακριβώς στη βάση**, πίνακες `hours` και
   `services`. Ζουν και στα δύο μέρη· βλ. ΠΑΡΑΔΟΣΗ.md §5.

   Τα υπόλοιπα αρχεία **δεν** χρειάζονται άγγιγμα: οι τίτλοι σελίδων,
   τα `og:` και τα δομημένα δεδομένα του Google παράγονται από εδώ με
   `node rebrand.mjs`, που το τρέχει αυτόματα το `publish.mjs`.

3. Στο `publish.mjs` άλλαξε το `REMOTE` στο **δημόσιο** repo. Και στον
   φάκελο του project: `git remote add origin <ιδιωτικό repo>` και
   `git push -u origin main`.

4. ```bash
   node publish.mjs "πρώτο ανέβασμα"
   ```

5. GitHub → **Settings → Pages** → Source: *Deploy from a branch* →
   `main` / `(root)` → Save. Ζωντανό σε 1-3 λεπτά.

## Γ. Email (10΄)

1. **resend.com** → εγγραφή με το email **του καταστήματος**, όχι το δικό
   σου. **API Keys** → Create → δικαίωμα *Sending access*. Αντίγραψε το
   `re_...` — δεν ξαναφαίνεται.

2. ```sql
   update settings set value = 're_ΤΟ_ΚΛΕΙΔΙ' where key = 'email_key';
   update settings set value = 'https://<το-site-σου>/' where key = 'site_url';
   update settings set value = 'email@καταστηματος' where key = 'email_owner';
   ```

3. Δοκιμή:

   ```sql
   select send_email_('email@καταστηματος', 'Δοκιμη',
                      email_shell_('Δοκιμη','<p>Δουλευει.</p>'));
   ```

   Κοίτα και τα **ανεπιθύμητα** — χωρίς δικό σου domain εκεί καταλήγει.

> **Σημαντικός περιορισμός:** χωρίς επαληθευμένο domain, το Resend στέλνει
> **μόνο** στη διεύθυνση του λογαριασμού. Οι πελάτες **δεν** θα παίρνουν
> email μέχρι το βήμα Δ. Γι' αυτό κράτα στο `config.js` το
> `customerEmails: false` — η φόρμα δεν θα ζητάει email και το
> διαχειριστικό δεν θα υπόσχεται ειδοποιήσεις που δεν φτάνουν.

## Δ. Domain (μετά την αγορά)

1. Αγόρασε **domain** στο όνομα του καταστήματος. Πριν πεις ναι σε πακέτο
   hosting, δες `ΚΟΣΤΟΛΟΓΙΟ.md` Β2: το GitHub Pages δεν επιτρέπεται για
   επιχείρηση, οπότε η επιλογή είναι δωρεάν πάροχος με εμπορική χρήση
   (Cloudflare Pages, Netlify) ή ελληνικό πακέτο με υποστήριξη. Τα βήματα
   2-3 παρακάτω είναι για το GitHub Pages, όπως τρέχει σήμερα.

2. **Στο GitHub** → Settings → Pages → *Custom domain* → γράψε το →
   Save → τσέκαρε *Enforce HTTPS*. Δημιουργείται αρχείο `CNAME`· το
   `publish.mjs` το διατηρεί αυτόματα.

3. **Στον καταχωρητή**, εγγραφές DNS:

   | Τύπος | Όνομα | Τιμή |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `<username>.github.io` |

   *(Επιβεβαίωσε τις διευθύνσεις στην τεκμηρίωση του GitHub Pages — έχουν
   αλλάξει στο παρελθόν.)*

4. **Resend → Domains → Add domain** → βάλε τις τρεις εγγραφές που θα σου
   δώσει (SPF, DKIM, DMARC) στον ίδιο πίνακα DNS. Μόλις επαληθευτεί:

   ```sql
   update settings set value = 'HAIR MANIA VALKANIS <ραντεβου@domain.gr>'
     where key = 'email_from';
   update settings set value = 'https://domain.gr/' where key = 'site_url';
   ```

5. Στο `config.js` γύρνα το `customerEmails: true` και τρέξε
   `node publish.mjs`. Από εκεί και πέρα η φόρμα ζητάει email και τα
   email φτάνουν σε οποιονδήποτε, στα εισερχόμενα.

## Ε. Έλεγχος ότι όλα δουλεύουν

- [ ] Η αρχική φορτώνει, το ωράριο δείχνει σωστά ανοιχτά/κλειστά
- [ ] Η σελίδα κράτησης δείχνει ώρες (όχι «δοκίμασε ξανά»)
- [ ] Δοκιμαστική κράτηση περνάει και βγάζει κωδικό
- [ ] Ο σύνδεσμος ακύρωσης δουλεύει
- [ ] Το διαχειριστικό δέχεται τον κωδικό
- [ ] Ημέρα και Εβδομάδα δείχνουν το ραντεβού
- [ ] Ακύρωση από το διαχειριστικό ελευθερώνει την ώρα
- [ ] GitHub → Actions → **keepalive** → *Run workflow* → πράσινο
- [ ] `node backup.mjs` κατεβάζει αρχείο με σωστά πλήθη
- [ ] Ωράριο και υπηρεσίες ίδια στο `config.js` και στη βάση
- [ ] Η φραγή δουλεύει: 11 λάθος κωδικοί στη σειρά στο διαχειριστικό →
      ο 11ος δείχνει «Πολλές λάθος προσπάθειες». Μετά ξεκλείδωσε με
      `delete from admin_attempts;`
- [ ] Τα δεδομένα **δεν** διαρρέουν — δύο έλεγχοι:

```bash
# 1. οι πίνακες είναι κλειδωμένοι
curl -s "https://<ref>.supabase.co/rest/v1/appointments" \
  -H "apikey: <anon key>"
# πρέπει: "permission denied for table appointments"

# 2. οι εσωτερικές συναρτήσεις είναι κλειστές
curl -s -X POST "https://<ref>.supabase.co/rest/v1/rpc/setting_" \
  -H "apikey: <anon key>" -H "Authorization: Bearer <anon key>" \
  -H "Content-Type: application/json" -d '{"k":"site_url"}'
# πρέπει: "permission denied for function setting_"
```

Αυτοί οι δύο είναι οι σημαντικότεροι. Αν ο πρώτος επιστρέψει δεδομένα,
κάποιος έχει προσθέσει πολιτική RLS ή δικαιώματα σε πίνακα. Αν ο
δεύτερος επιστρέψει τιμή, λείπει το `patch-04-security.sql` — και τότε
**και ο κωδικός του διαχειριστικού διαβάζεται από οποιονδήποτε**.
Διόρθωσέ το αμέσως, και μετά άλλαξε κωδικό και κλειδί Resend.

> Ο δεύτερος έλεγχος ζητάει επίτηδες το `site_url`, που δεν είναι μυστικό
> — ώστε, αν ο έλεγχος αποτύχει, να μην τυπωθεί κωδικός στην οθόνη.
