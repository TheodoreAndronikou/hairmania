# Εγκατάσταση από το μηδέν

Πώς στήνεται όλο το σύστημα σε καθαρούς λογαριασμούς. Χρειάζεται αν
μεταφέρεις το έργο σε νέα ιδιοκτησία ή αν το ξαναστήνεις για άλλο μαγαζί.

Χρόνος: ~40 λεπτά.

> **Οι παλιές οδηγίες αυτού του αρχείου (Google Apps Script + Google
> Calendar) είναι άκυρες.** Η αρχιτεκτονική άλλαξε σε Supabase τον
> Σεπτέμβριο 2026. Το Apps Script δεν χρησιμοποιείται πουθενά.

Δες πρώτα το **ΠΑΡΑΔΟΣΗ.md** για το τι είναι το κάθε κομμάτι.

---

## Α. Η βάση (15΄)

1. **supabase.com** → Sign in with GitHub → **New project**.
   Περιοχή: *Frankfurt* (πλησιέστερη στην Ελλάδα).
   Κράτα τον κωδικό της βάσης που θα σου δώσει.

2. **SQL Editor** → New query → επικόλλησε **όλο** το `supabase/schema.sql`
   → **Run**.

   > Τρέξε **ΧΩΡΙΣ RLS**. Ο SQL Editor μπορεί να σε ρωτήσει. Οι πίνακες
   > είναι σκόπιμα κλειδωμένοι· με RLS ενεργό τα `insert` δεν περνάνε και
   > **δεν παίρνεις μήνυμα λάθους**.

3. Ίδια διαδικασία για `supabase/patch-01.sql` και
   `supabase/patch-02-email.sql`, με αυτή τη σειρά.

4. **Settings → API** → αντίγραψε *Project URL* και *anon public key*.

5. Άλλαξε τον κωδικό του διαχειριστικού από το εργοστασιακό `1234`:

   ```sql
   update settings set value = 'δικος_σου_κωδικος' where key = 'admin_pin';
   ```

   Αν ξεχαστεί, το διαχειριστικό εμφανίζει κόκκινη προειδοποίηση.

---

## Β. Το site (10΄)

1. Νέο repository στο GitHub, **Public** (χρειάζεται για δωρεάν Pages και
   Actions).

2. Στο `site/assets/js/config.js` βάλε τα στοιχεία του βήματος Α4:

   ```js
   SUPABASE: {
     url: 'https://<ref>.supabase.co',
     key: 'eyJ...'          // δημόσιο anon key — σωστά ορατό
   }
   ```

   Στην ίδια ενότητα ενημέρωσε τηλέφωνα, διεύθυνση, social.

3. Στο `publish.mjs` άλλαξε το `REMOTE` στο νέο repo.

4. ```bash
   node publish.mjs "πρώτο ανέβασμα"
   ```

5. GitHub → **Settings → Pages** → Source: *Deploy from a branch* →
   `main` / `(root)` → Save. Ζωντανό σε 1-3 λεπτά.

---

## Γ. Email (10΄)

1. **resend.com** → εγγραφή με το email **του καταστήματος**, όχι το δικό
   σου. **API Keys** → Create → δικαίωμα *Sending access*. Αντίγραψε το
   `re_...` — δεν ξαναφαίνεται.

2. ```sql
   update settings set value = 're_ΤΟ_ΚΛΕΙΔΙ' where key = 'email_key';
   update settings set value = 'https://<το-site-σου>/' where key = 'site_url';
   update settings set value = 'email@καταστηματος' where key = 'email_owner';
   ```

3. Δοκιμή:

   ```sql
   select send_email_('email@καταστηματος', 'Δοκιμη',
                      email_shell_('Δοκιμη','<p>Δουλευει.</p>'));
   ```

   Κοίτα και τα **ανεπιθύμητα** — χωρίς δικό σου domain εκεί καταλήγει.

> **Σημαντικό περιορισμός:** χωρίς επαληθευμένο domain, το Resend στέλνει
> **μόνο** στη διεύθυνση του λογαριασμού. Οι πελάτες **δεν** θα παίρνουν
> επιβεβαιώσεις μέχρι το βήμα Δ.

---

## Δ. Domain (μετά την αγορά)

1. Αγόρασε **σκέτο domain** στο όνομα του καταστήματος. Αρνήσου τα πακέτα
   hosting — δεν χρειάζονται, η φιλοξενία είναι δωρεάν στο GitHub.

2. **Στο GitHub** → Settings → Pages → *Custom domain* → γράψε το →
   Save → τσέκαρε *Enforce HTTPS*. Δημιουργείται αρχείο `CNAME`· το
   `publish.mjs` το διατηρεί αυτόματα.

3. **Στον καταχωρητή**, εγγραφές DNS:

   | Τύπος | Όνομα | Τιμή |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `<username>.github.io` |

   *(Επιβεβαίωσε τις διευθύνσεις στην τεκμηρίωση του GitHub Pages — έχουν
   αλλάξει στο παρελθόν.)*

4. **Resend → Domains → Add domain** → βάλε τις τρεις εγγραφές που θα σου
   δώσει (SPF, DKIM, DMARC) στον ίδιο πίνακα DNS. Μόλις επαληθευτεί:

   ```sql
   update settings set value = 'HAIR MANIA VALKANIS <ραντεβου@domain.gr>'
     where key = 'email_from';
   update settings set value = 'https://domain.gr/' where key = 'site_url';
   ```

Από εδώ και πέρα τα email φτάνουν σε οποιονδήποτε, και στα εισερχόμενα.

## Ε. Έλεγχος ότι όλα δουλεύουν

- [ ] Η αρχική φορτώνει, το ωράριο δείχνει σωστά ανοιχτά/κλειστά
- [ ] Η σελίδα κράτησης δείχνει ώρες (όχι «δοκίμασε ξανά»)
- [ ] Δοκιμαστική κράτηση περνάει και βγάζει κωδικό
- [ ] Ο σύνδεσμος ακύρωσης δουλεύει
- [ ] Το διαχειριστικό δέχεται τον κωδικό
- [ ] Ημέρα και Εβδομάδα δείχνουν το ραντεβού
- [ ] Ακύρωση από το διαχειριστικό ελευθερώνει την ώρα
- [ ] GitHub → Actions → **keepalive** → *Run workflow* → πράσινο
- [ ] Τα δεδομένα **δεν** διαρρέουν:

```bash
curl -s "https://<ref>.supabase.co/rest/v1/appointments" \
  -H "apikey: <anon key>"
# πρέπει: permission denied for table appointments
```

Το τελευταίο είναι το σημαντικότερο. Αν επιστρέψει δεδομένα, κάποιος έχει
προσθέσει πολιτική RLS ή δικαιώματα σε πίνακα — **διόρθωσέ το αμέσως**,
είναι διαρροή προσωπικών δεδομένων πελατών.
